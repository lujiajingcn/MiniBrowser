# 2026-09-04

## STUN 报错排查（npm start 时的 socket_manager.cc 噪音）
- 现象：`npm start` 后控制台刷 `ERROR:socket_manager.cc(141) Failed to resolve address for stun.services.mozilla.com., errorcode: -105`（-105 = ERR_NAME_NOT_RESOLVED）。
- 结论：**无害噪音，应用本身正常启动**。这是 Chromium WebRTC 网络层在解析 STUN 服务器时 DNS 失败，来自某个正在打开的网页（很可能是 `restoreSession` 恢复的标签页里用了 WebRTC 的站点），不是 MiniBrowser 代码 bug。
- 证据：grep 项目自有代码（main/renderer/preload/webview-preload/index.html/styles.css）**零 WebRTC 使用**；受控实验里 `new RTCPeerConnection({iceServers:[{urls:'stun:stun.services.mozilla.com'}]})` 会触发，但沙箱无显示环境不一定打印该日志行。
- **重要坑**：想用 `app.commandLine.appendSwitch('disable-features','WebRtc')` 关掉 WebRTC —— **在 Electron 31 无效**。受控实验验证：加该开关后渲染进程 `typeof RTCPeerConnection` 仍为 `function` 且可 `constructed`。Electron 无干净的 webPreferences 开关能禁用 WebRTC；强行剥离 `RTCPeerConnection` 会破坏视频会议/语音等实时站点。
- 处理建议：此类报错默认"保持现状"，仅影响该网页的实时通信能力，不影响普通浏览。若要消除噪音，优先定位并关闭触发 WebRTC 的那个标签页，而非全局禁用 WebRTC。
